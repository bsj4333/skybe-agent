# SKIVE 목표와 비목표

배경과 상세 근거는 `SKIVE_NEXT_PLAN.md`(동결)에 있다. 이 파일은 지금 판단에 필요한 것만 담는다.

## 한 줄 목표

대학생이 자기 드라이브에 과제·프로젝트 자료를 그대로 올려두면, SKIVE가 그 자료를 읽고 **근거가 붙은 경험 기록**으로 정리해 두었다가, 공부할 때와 지원서를 쓸 때 **자료에 있는 사실만으로** 도와준다.

## 핵심 약속

다른 서비스와 구별되는 지점이다. 이게 깨지면 SKIVE를 쓸 이유가 없다. 상세 규칙은 `AGENTS.md` §5.

- 모든 문장은 어느 파일의 어느 위치에서 나왔는지 열어볼 수 있다.
- 팀이 한 일을 본인이 한 일로 바꾸지 않는다. 확실하지 않으면 사용자에게 묻는다.
- 사용자가 정정하면 그 뒤로는 정정된 사실만 쓴다.

## 12월 데모에서 보여줄 장면

1. 보고서·발표자료·코드가 든 실제 프로젝트 폴더를 올린다.
2. 파일별 읽기 상태를 보고, 파일을 활동 단위로 묶는다.
3. 활동의 사실 후보를 확인하고 역할 질문에 답해 활동 요약 MD를 만든다.
4. 챗봇에게 세부 내용을 묻고, 답의 근거 문장을 눌러 원문을 연다.
5. 공고를 넣어 문항별 초안을 만들고, 문장마다 근거를 확인한다.
6. 성과 수치를 정정하면 기존 초안에 "갱신 필요"가 뜬다.
7. 새 대화에서 정정된 최신 사실을 정확히 기억한다.

이 한 흐름을 실제 자료로 안정적으로 해내는 것이 기능 개수를 늘리는 것보다 우선이다.

## 비목표 (12월까지 하지 않는 것)

- 자동 공고 검색·크롤링, 주간 알림, 복습 엔진, 자유 진로 상담
- 스캔 PDF OCR, 이미지·영상 내용 이해 (필요성이 시뮬에서 크게 드러나면 재검토)
- 20명을 넘는 규모를 위한 확장 설계
- 실시간 Google Drive 동기화 (스냅샷 가져오기만)
- 사람 검토 없는 완전 자율 에이전트 루프
- 레거시 단일 사용자 엔진(`legacy_server`, `data/`)의 기능 추가. 회귀 테스트만 유지한다

## 성공 기준 (측정 방식)

수치는 목표치이지 현재 성능이 아니다. 표본이 작으면 분자/분모를 함께 적는다.

| 지표 | 목표 |
|---|---|
| 계정 간 접근·미승인 변경 | 고정 회귀 케이스 0건. 하나라도 있으면 배포 중단 |
| 정정 뒤 옛 사실 재등장 | 0건 |
| 근거 정확도 (인용이 주장을 실제로 지지) | 95% 이상 |
| 검색 Recall@5 (필수 근거가 상위 5개에 포함) | 90% 이상 |
| 텍스트 추출 가능 비율 | 실자료별로 보고. 미지원 원인별 분류 |
| 처리 시간·비용 | 작업별 p50/p95, 사용자당 월 비용 보고 |

## 제약

- 개발: 사람 1명 + Codex(구현) + Claude(설계·평가)
- 비용: Supabase Pro 고정비 + OpenAI 종량제. 유료 호출은 `AGENTS.md` §8 상한을 따른다
- 환경: Windows 개발 PC, 한글 경로, 공유 Supabase 프로젝트 하나
- 모델: `gpt-6-luna`(기본)와 `gpt-6-sol`(중요 작업). `gpt-6-astra`는 쓰지 않는다. 작업별 배치는 `build/design-model-routing.md`. 현재 코드는 아직 `gpt-4o-mini`/`gpt-4o` (F-205에서 전환)
