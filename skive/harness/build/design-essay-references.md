## 이 문서를 언제 쓰는가

자소서 작성 흐름, 문항 분석, 초안 검사, 면접 준비, 경력기술서 양식을 설계하거나 고칠 때 먼저 읽는다. 외부 자료의 내용을 그대로 복사하지 않고, 아이디어만 스카이브의 근거 규칙에 맞게 다시 설계한다.

## 2. 스카이브와의 차이

두 자료는 작성 방법과 양식이 강하지만, 문장이 어느 파일의 어느 위치에서 나왔는지 코드로 대조하지 않는다. 스카이브의 차별점은 그 대조다. 따라서 외부 노하우는 **근거 검증 뒤에 얹는 작성 품질 층**으로만 쓴다. 충돌하면 `AGENTS.md` §5 불변조건이 이긴다.

## 3. 지금 설계에 반영 (F-203 다음 순서)

| 항목 | 내용 | 모델 비용 | 완료 조건 (관찰 가능) |
|---|---|---|---|
| F-211 규칙 기반 초안 점검 | AI풍 표현, 일반론 시작, 수치 없는 성과 동사, 접속어 중첩을 코드로 찾아 문장 위치와 이유를 표시한다 | 없음 | 합성 초안의 각 패턴이 해당 문장 위치와 함께 보고된다. 사실 문장을 자동으로 고치지 않는다 |
| F-212 치환 테스트 | 회사명을 경쟁사로, 주어를 다른 지원자로 바꿔도 성립하는 지원동기 문장을 표시한다 | 낮음 | 실패 문장에 이유가 붙고, 사용자에게 질문으로 이어진다 |
| F-213 날조 없는 고쳐쓰기 | 진단 → 질문 → 사용자 답변과 확인된 사실로만 재작성 → 재진단. 답변은 `user_statement`로 저장한다 | 초안 모델 | 재작성 문장에 근거 없는 새 수치·행동이 생기면 저장되지 않는다 |
| F-214 꼬리질문 맵 | 문장마다 예상 질문 2개 이상, 유형(수치·기술선택·역할범위·성과·갈등판단), 준비 상태(준비됨·부족·미준비)를 만든다 | 낮음 | 근거가 연결되지 않은 문장은 `미준비`로 표시된다. 답변 요약은 사용자가 확인하기 전에는 비어 있다 |

자소서 프롬프트에 함께 반영할 규칙:

- 문항 의도를 먼저 뽑고 그 의도에 답하게 한다.
- 결론 → 근거 수치 → 입사 후 기여 순서로 쓴다. 첫 문장에 가장 차별화된 확인된 경험을 둔다.
- 공고 키워드의 반영률을 보여주되, 경험이 없는 키워드를 넣으려고 문장을 만들지 않는다.

## 4. 나중에 참고 (자소서 양식화 단계)

- 경력기술서 양식: 최신순 정렬, `2023.03 ~ 2023.10 (7개월)` 기간 표기, 성과(팀)와 역할(개인) 분리, 개조식, 기술 스택 중요도순, 지원 공고에 맞는 프로젝트 선별.
- 기간이 자료에 없으면 추정해서 채우지 않는다. 외부 스킬의 "기간 미지정 시 적정 기간 산정" 규칙은 쓰지 않고 사용자에게 묻는다.
- 신입·경력 구분 첨삭, NCS 역량 매핑, 직무별 소재표, 면접 유형별 시뮬레이션, 지원 후 회고.

## 5. 그대로 쓰지 않는 것

| 외부 규칙 | 문제 | 스카이브 처리 |
|---|---|---|
| "수치가 없으면 성과가 아니다" | 모델이 수치를 지어내게 유도한다 (불변조건 4) | 수치가 없으면 빈칸으로 두고 사용자에게 묻는다 |
| 미끼 문장 배치 | 확인 안 된 경험이 들어갈 수 있다 (불변조건 1, 2) | 확인된 사실에만 꼬리질문을 만든다 |
| "학생 톤 제거, 즉시 투입 가능한 실무자" | 역할이나 성과를 부풀릴 수 있다 | 문체만 다듬고 주체와 범위는 바꾸지 않는다 |
| 채용 사이트 수집 | 12월까지의 비목표 | 공고는 사용자가 입력한다 |
| AI 탐지 회피 약속 | 탐지 결과를 보장할 수 없다 | 화면과 문서에서 약속하지 않는다 |
