# phase-02: 근거 있는 검색과 작성

> 작성: Claude · 상태: spec (phase-01 결과를 받아 확정) · 관련 항목: F-201, F-202, F-203, F-204

## 1. 목적

이미 확인된 두 결함이 SKIVE의 핵심 약속을 막고 있다.

1. **챗봇이 정답 자료를 못 찾는다.** 화력발전소 오탐 감소 질문에서 키워드 검색이 `report.md`를 상위 10개 안에 넣지 못했다. 같은 원문을 직접 주면 `gpt-4o-mini`도 수치 6개를 전부 맞혔다. 병목은 모델이 아니라 검색이다. (`AGENTS_API_COMPARISON_2026-09-28.md`)
2. **새 드라이브 경로에는 문장별 근거 검증이 없다.** 레거시 `writer.py`의 문장 ID 판정·커버리지 검사·최종 재검증(F04)이 새 챗봇·자소서 경로에 이식되지 않았다. 지금 자소서는 항상 "검토 필요"다.

phase-01에서 새로 나오는 P2 결함도 여기서 함께 설계한다.

## 2. 순서: 측정 먼저

| 순서 | 항목 | 내용 |
|---|---|---|
| 1 | F-201 고정 평가셋 v0 | phase-01의 실패 질문 20건 이상. 각 건: 질문, 계정·범위, 필수 근거 파일·위치, 기대 답, 금지 주장. 결정론적으로 채점할 수 있는 부분(Recall@5, 금지 수치 등장 여부)과 사람이 판정할 부분을 나눈다 |
| 2 | F-202 검색 개선 | 평가셋으로 현재 Recall@5를 먼저 잰다. 그다음 폴더 경로·파일 종류 가중, 결과 요약 파일(`report.md`, `run_summary.txt` 등) 우선, 동의어·재검색을 한 번에 하나씩 바꾸며 비교한다 |
| 3 | F-203 문장별 근거 검증 이식 | 새 자소서·챗봇 답변에 레거시의 문장 ID 판정, 판정 누락 검사, 삭제 후 재검증을 적용한다. 판정 모델은 `gpt-4o` |
| 4 | F-204 프로젝트 통합 요약 품질 | OpenAI 한도가 풀리면 화력발전소 1개 폴더로 재실행해 검증 통과 근거 수를 첫 실행(1개)과 비교한다 |
| 5 | F-211~F-214 자소서 작성 품질 | 근거 검증이 끝난 뒤 규칙 점검, 치환 테스트, 날조 없는 고쳐쓰기, 꼬리질문 맵 순서로 넣는다. `design-essay-references.md` |

검색 개선과 모델 교체를 동시에 하지 않는다. 무엇이 효과를 냈는지 알 수 없게 된다.

## 3. 완료 조건 (phase-01 결과에 따라 확정)

- [ ] (deterministic) 평가셋 채점 스크립트가 유료 호출 없이 Recall@5를 계산한다
- [ ] (live) 평가셋 v0에서 Recall@5를 변경 전·후로 기록한다. 목표 90%
- [ ] (deterministic) 새 자소서 경로에 판정 누락·삭제 실패 시 "통과"로 표시하지 않는 회귀 테스트가 있다
- [ ] (real_data) 화력발전소 오탐 감소 질문에 수치 6개와 출처를 정확히 답한다

- Agents API 방식의 재검색 루프를 제한된 범위(검색 실패 시만, 횟수·시간·비용 상한)로 도입할지
