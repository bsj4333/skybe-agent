# 설계: 파일 종류별 처리 방침

> 작성: Claude (2026-09-30) · 상태: **spec — 사람 승인 필요** · 관련 항목: F-107, F-207, F-208, F-209, F-210

## 1. 목적

사용자는 과제·프로젝트 폴더를 **있는 그대로** 올린다. 그 안에는 문서뿐 아니라 압축 파일, 원시 데이터 CSV, 학습된 모델 가중치, 영상, 3D 출력 파일이 섞여 있다. 2026-09-29 실제 업로드(파일 3,246개, 약 47.6GB)의 구성은 아래와 같았다.

| 종류 | 개수 | 용량 | 현재 처리 |
|---|---:|---:|---|
| 압축 (zip) | 41 | 20.9GB | 미지원 |
| 표 데이터 (csv, xlsx, json/jsonl, twbx) | 1,007 | 18.1GB | csv·xlsx·json 지원(50MiB 이하), twbx 미지원 |
| 모델 가중치 (safetensors, pt) | 6 | 3.7GB | 미지원 |
| 영상 (mp4) | 3 | 2.2GB | 미지원 |
| 문서 (pdf, docx, pptx, md, txt) | 246 | 1.1GB | 지원 |
| 이미지 (png, jpg) | 1,558 | 0.5GB | 미지원 |
| 3D·CAD·GIS (stl, gcode, 3mf, shp) | 42 | 0.1GB | 미지원 |
| 코드·노트북 (py, ipynb, js, html) | 318 | 14MB | py·js·html 지원, **ipynb 미지원** |

용량의 90% 이상이 원시 데이터·압축·가중치·영상이다. 경험을 설명하는 핵심 근거(문서, 코드, 노트북, 결과 표)는 용량으로는 작다. 원칙은 **"원본은 전부 보관하고, 분석은 종류에 맞게 다르게 한다"** 이다.

## 2. 종류별 방침

| 종류 | 보관 | 분석 방식 | 모델 사용 |
|---|---|---|---|
| **문서** (pdf, docx, pptx, md, txt, hwp는 추후) | 원본 | 본문 전체 + 주석·발표자 노트·메모를 위치와 함께 추출 (현재 구현) | 추출은 없음. 사실 후보 단계에서 luna |
| **코드** (py, js, html, R, sql 등) | 원본 | 텍스트 추출 (현재 구현). import·함수 이름은 기술 스택 근거 | 없음 |
| **노트북** (ipynb) | 원본 | **마크다운 셀 + 코드 셀 + 텍스트 출력**을 셀 번호 위치로 추출. 그림 출력(base64)은 버리고 "그림 출력 있음"만 기록 | 없음 |
| **표 데이터** (csv, tsv, xlsx, jsonl) | 원본 | **내용 전체를 모델에 넣지 않는다.** 행 수·열 이름·결측·수치 통계·주요 지표 최댓값의 행 번호와 샘플 몇 행만 색인한다 (csv는 현재 구현). 50MiB 초과 파일은 **앞부분만 읽는 스트리밍 요약**(열 구조, 샘플, 읽은 범위 표시)으로 처리 | 없음 |
| **압축** (zip) | 원본 zip 그대로 | ① **목차 색인**: 압축을 풀지 않고 내부 파일 목록·경로·크기를 읽어 드라이브에 "zip 안의 폴더"로 보여준다. ② **선택 해제**: 내부 파일 중 문서·코드·노트북·작은 표(각 50MiB 이하)만 풀어서 위 규칙으로 분석한다. 원시 데이터·가중치·영상은 풀지 않고 목록만 남긴다. 중첩 zip은 1단계까지 | 없음 |
| **모델 가중치** (safetensors, pt, pth, onnx, pkl) | 원본 | 내용 분석 안 함. **이름·크기·위치 메타데이터만 색인.** "이 프로젝트에 학습된 모델이 있다"는 사실 자체가 근거가 된다. safetensors는 헤더(텐서 이름·모양)만 읽는 것을 추후 검토 | 없음 |
| **이미지** (png, jpg) | 원본 | 지금은 메타데이터(이름·폴더·크기)만 색인. 결과 그래프가 많아 추후 이미지 이해를 검토(F-301) | 추후 |
| **영상·음성** (mp4, mp3) | 원본 | 메타데이터만. 재생·다운로드는 가능 | 없음 |
| **3D·CAD·GIS** (stl, 3mf, gcode, shp) | 원본 | 메타데이터만. gcode는 앞부분 주석(프린터·설정)을 텍스트로 읽는 것을 추후 검토 | 없음 |
| **Tableau** (twbx, twb) | 원본 | 추후: twbx 안의 twb XML에서 시트·필드 이름 추출 | 없음 |
| **개발 부산물** (css, 폰트, .gitignore, .gitkeep) | 원본 | 메타데이터만. 검색 결과에서는 뒤로 | 없음 |

**모든 파일은 최소한 메타데이터로 색인한다.** 지금은 미지원 파일이 검색에 아예 안 잡힌다. 이름·경로·크기·종류만 있어도 "그 대회 때 만든 모델 파일 있었지?" 같은 질문에 답할 수 있다.

## 3. 압축 파일을 전부 풀지 않는 이유

- 2026-09-29 업로드의 zip은 41개, 20.9GB다. 전부 풀면 Storage 사용량이 두 배 가까이 된다.
- 큰 zip의 대부분은 대회 데이터셋·출력 영상 같은 원시 자료다. 경험 근거는 그 안의 소수 문서·코드다.
- zip 목차(central directory)는 파일 끝부분만 읽으면 되므로 수 GB짜리 zip도 전체를 내려받지 않고 목록을 만들 수 있다(HTTP Range 요청).
- 사용자에게는 zip이 폴더처럼 열리므로 "드라이브는 원본 그대로" 원칙과 맞는다. zip 원본은 그대로 남는다.

안전장치: 경로 탈출(`../`) 거부, 압축 해제 합계·파일 수 상한(zip bomb), 중첩 1단계, 암호 zip은 "암호 걸림"으로 표시.

## 4. 저장 공간과 요금제 (중요)

- **현재 Supabase 무료 플랜:** Storage 1GB, 파일당 업로드 50MB, 이그레스(내려받기) 캐시 5GB + 비캐시 5GB.
- 현재 Storage 사용량 약 47GB = **무료 한도의 약 47배.** 무료 플랜은 초과 즉시 막지 않고 경고 메일 후 유예 기간을 준다. 유예가 끝나면 **프로젝트 전체가 제한될 수 있다**(DB·로그인 포함). 파일당 50MB 제한은 업로드 도구가 큰 파일을 조각(`parts/N`)으로 나눠 피했다.
- 추출 워커는 원본을 내려받아 읽는다. 이번 업로드를 전부 추출하면 이그레스가 무료 한도를 넘는다.
- 원시 데이터를 전부 빼도 문서·이미지·코드와 기존 자료만으로 약 2GB라서 **무료 플랜으로는 부족하다.** 사용자 1명 규모에서 이미 넘으므로 베타 전에는 Pro가 필요하다.

## 6. 불변조건 영향

- "드라이브는 원본 그대로": zip 원본을 지우거나 바꾸지 않는다. zip 내부 목록은 원본의 파생 보기로 표시한다.
- 표 데이터·메타데이터만 있는 파일에서 개인 역할이나 성과를 추론하지 않는다.
