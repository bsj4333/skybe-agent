# SKIVE의 현재 4o-mini 경로와 Agents API 실자료 비교

2026-09-28, 현재 Supabase에 올라온 한 계정의 파일을 **읽기 전용**으로 조회했다. 새 파일을 올리거나 SKIVE의 대화·경험·자소서 기록을 변경하지 않았다. Agents API에 만든 임시 세션은 시험 후 삭제했다.

## 시험 질문

> 화력발전소 이상탐지의 오탐 감소 실험에서 F1 최고 후보와 운영 추천 후보의 F1, 이상 발생 전 오탐률, 리드타임을 비교해줘. 이 자료만으로 내가 직접 모델을 만들었다고 말할 수 있는지도 구분해줘.

판정 기준은 업로드된 `2. 화력발전소 이상탐지/사용자A/분산 클러스터링 방법/6. false_alarm_reduction/outputs/report.md`의 첫 번째 읽기 구간이다.

| 항목 | F1 최고 후보 | 운영 추천 후보 |
|---|---:|---:|
| F1 | 0.2254 | 0.2061 |
| 이상 발생 전 오탐률 | 0.5294 | 0.0588 |
| 리드타임 | 197분 | 107분 |

보고서는 실험 결과를 제시하지만, 계정 주인이 모델을 직접 만들었는지는 증명하지 않는다.

## 실행 결과

| 경로 | 실제 검색 | 답변 | 경과 시간 |
|---|---|---|---:|
| 현재 SKIVE 방식 + gpt-4o-mini | `_keywords` 1회, `_sources` 1회. 상위 10개에 `report.md` 없음 | 수치를 찾을 수 없다고 답함. 개인 역할은 단정하지 않음 | 47.08초 |
| Agents API + gpt-6-astra | 같은 SKIVE 검색 함수를 도구로 9회 호출하고 원문 구간을 3회 다시 읽음. 전체 46개 구간을 발견했고 `report.md`에 도달 | 위 수치 6개를 모두 맞힘. 전체 오탐률은 오히려 높다는 제한과 개인 역할 확인 질문을 제시. `report.md`와 CSV 출처 표시 | 331.49초 |
| 정확한 `report.md`를 직접 제공한 gpt-4o-mini | 검색 생략, 동일한 한국어 질문과 원문 제공 | 위 수치 6개를 모두 맞히고 개인 역할을 단정하지 않음 | 모델 호출 3.10초 |

Agents API 쪽은 모델이 스스로 검색어를 바꾸고 재검색해서 누락된 근거를 찾아냈다. 그러나 5분 31초가 걸렸고, 관련 없는 KT 파일도 검색 결과에 많이 섞였다. 이 한 번의 시험으로 모델 우열이나 일반적인 정확도를 판단할 수 없다. 모델(`gpt-4o-mini` vs `gpt-6-astra`)과 검색 횟수가 동시에 달랐기 때문이다. 통제 시험은 4o-mini도 올바른 원문만 받으면 정확히 답한다는 점을 보여준다.

세부 수치 검증은 여전히 필요하다. Agents API 답변은 질문한 핵심 지표 6개를 맞혔지만, 추가로 제시한 운영 후보의 전체 오탐률은 81.88%라고 적었다. `report.md`의 표기는 0.8187(81.87%)이다.

## 확인된 병목과 다음 작업

1. **검색 개선이 우선:** 현재 `_sources`는 단어의 파일명·본문 일치 점수를 합쳐 전역 상위 결과를 뽑는다. 이 질문에서는 관련 CSV보다 다른 프로젝트 자료가 섞여 요약 보고서를 놓쳤다. 폴더 경로, 파일 종류, 결과 요약 파일, 동의어를 고려한 재검색과 재순위화가 필요하다.
2. **Agents API는 제한된 단계에 도입:** 검색 실패 시 재검색을 맡기거나, 답변 근거가 불충분하면 원문을 다시 읽게 하는 방식이 유효해 보인다. 검색 횟수·시간·비용 상한을 두고 출처 없는 문장은 막아야 한다.
3. **인용을 제품 출처에 연결:** 시험의 `[S번호]`는 세션 내부 임시 번호다. 실제 제품에서는 사용자 권한을 검사한 파일 ID·구간·원문 미리보기 링크로 연결해야 한다.
4. **다른 자료로 반복 평가:** KT, 수업 자료, 여러 파일에 흩어진 경험, 근거 없는 본인 역할 질문을 같은 기준으로 테스트해야 한다.

시험 스크립트: `scripts/compare_agents_api.py`. 실행 시 `DATABASE_URL`의 5432 연결이 시간 초과되어, **시험 프로세스에서만** Supabase pooler의 6543 포트를 사용했다. 앱 설정은 바꾸지 않았다.
