## 분석 품질에서 확인한 것

- KT의 `kt_정리_최신본.md`는 7개 원문 구간으로 추출됐다. 프로젝트 목적과 평가 설계의 실제 문장은 보존된다.
- 화력발전소의 3,725,546바이트 CSV를 실제로 10,080행 전체 스캔해 36개 열의 수치 통계, F1 최대값과 원본 행 번호를 약 7.7KB로 저장했다. 원본은 Storage에 남는다.
- 건설장비의 작은 XLSX는 시트·행·셀 주소와 값이 추출된다. 25MB 원시 센서 XLSX는 전체 셀 추출이 지나치게 느려 원본만 보관하고 미지원으로 표시한다.
- 화면의 **읽기**는 구간 목록과 원문 미리보기를 보여준다. 현재 생성되는 Markdown은 **추출 위치 색인**이다. 파일을 종합한 사실 요약, 사용자 본인 기여·성장·수치 검증, 자소서 소재 추천은 아직 새 멀티유저 드라이브에 연결되지 않았다.

## 범위와 남은 문제

- `종합설계` 전체는 5,132개·38,443,671,269바이트다. 건설장비 쪽 4,761개·38,164,266,892바이트는 대부분 중간 CSV이며, 사용자는 핵심 자료 분석 후 대용량 원본을 추후 업로드하기로 선택했다. 현재 업로드한 건설장비 자료는 9개뿐이다.
- 미지원 313개의 주요 유형은 PNG 250개, CSS 31개, ZIP 11개, WOFF/WOFF2 각 10개, 5MB 초과 XLSX 1개다. 이미지 OCR과 압축 파일 내부 탐색, 대형 XLSX의 스트리밍 프로파일러가 필요하다.
- 브라우저에서 사용자가 폴더 선택 버튼을 직접 누르는 UI 동선은 자동 브라우저 제어 도구의 현재 URL 확인 문제로 클릭 검증을 완료하지 못했다. 대신 실제 업로드를 터미널에서 수행하고 API·DB·Storage·워커와 응답 HTML을 검증했다.
- 실사용 제품의 다음 핵심은 프로젝트별 파일 묶음, 상충하는 구버전 식별, 수치와 주체의 원문 인용, 본인 기여 확인을 갖춘 경험 요약이다. 이 단계 전에는 추출 색인을 자소서·면접 챗봇의 검증된 기억처럼 사용하면 안 된다.
- 친구가 자기 계정으로 다른 PC에서 접속하려면 HTTPS 배포가 필요하다. `localhost`는 현재 PC에서만 열린다.
