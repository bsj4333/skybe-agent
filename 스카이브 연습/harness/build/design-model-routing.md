# 설계: 사용자 작업별 모델·실행 방식 배치

> 작성: Claude (2026-09-29, 2026-09-30 개정) · 상태: **spec — 사람 승인 필요** · 관련 항목: F-106, F-205, F-206

## 0. 결론

- **모델은 `gpt-6-luna`(기본)와 `gpt-6-sol`(중요 작업) 두 개로 간다.** `gpt-4o-mini`는 luna 전환 검증 전까지의 예비, `gpt-4o`는 퇴역, **`gpt-6-astra`는 쓰지 않는다**(사람 결정, 2026-09-30).
- **sol이 `gpt-4o`보다 낫다.** 입력이 더 싸고($2 vs $2.50), 출력은 같고($10), 에이전트·추론 성능은 한 세대 위다.
- **luna가 `gpt-4o-mini`보다 싸다.** 입력 $0.10 vs $0.15, 출력 $0.50 vs $0.60. 문맥 창은 105만 토큰이다. 한국어 추출 품질만 평가셋으로 확인하고 기본값을 바꾼다.
- **사용자 쪽 비용 상한은 두지 않는다.** 폭주를 막는 안전장치(도구 회전 수, 시간, 출력 토큰 상한, 크레딧 소진 시 중단)만 둔다. 돈의 최종 상한은 OpenAI 조직 월 예산 하나로 건다.

## 1. 가격 (2026-09-30 확인, 100만 토큰당)

| 모델 | 입력 | 캐시 입력 | 출력 | 비고 |
|---|---:|---:|---:|---|
| `gpt-6-luna` | $0.10 | $0.01 | $0.50 | 2026-09-22 출시. 추론 강도 none~max, 기본 medium |
| `gpt-6-sol` | $2.00 | $0.20 | $10.00 | 2026-09-22 출시. 추론 강도 none~max, 기본 medium |
| `gpt-4o-mini` | $0.15 | $0.075 | $0.60 | 현재 기본값 |
| `gpt-4o` | $2.50 | $1.25 | $10.00 | 현재 판정 모델 |
| `gpt-6-astra` | $10.00 | $1.00 | $50.00 | **사용 금지** |
| `text-embedding-3-small` | $0.02 | — | — | 검색용 임베딩 |

출처: OpenAI 모델 문서(`developers.openai.com/api/docs/models/gpt-6-luna`, `.../gpt-6-sol`), 가격 문서. 9/29에 헷갈렸던 "5.6 sol/luna"는 이전 세대(GPT-5.6, luna $1/$6)이고 여기서는 쓰지 않는다.

### 구현 전에 알아야 할 두 가지

1. **luna와 sol은 추론 모델이다.** 보이지 않는 추론 토큰도 **출력 요금**으로 청구된다. 기본 강도가 medium이라 그냥 쓰면 단순 작업에도 출력 비용이 몇 배로 뛴다. **작업마다 추론 강도를 명시한다**(§3의 표).
2. **Chat Completions에서는 추론 강도가 `none`일 때만 도구 호출(function calling)이 된다.** 에이전트 루프(`drive_orchestrator.py`의 `bind_tools`)에 luna·sol을 쓰려면 **Responses API**로 바꿔야 한다(LangChain `ChatOpenAI(use_responses_api=True)`). 구조화 출력은 두 API 모두 지원한다.

## 2. 세 가지를 따로 정한다

| 축 | 선택지 | 결정 기준 |
|---|---|---|
| 작업 방식 | 워크플로 / 에이전트 | 다음 단계가 입력에 따라 달라지는가? 다시 찾거나 되묻는 판단이 필요한가? |
| 모델 | 없음 / luna / sol | 틀렸을 때 피해가 큰가(사용자가 제출하는 글, 기록으로 남는 요약)? 호출이 많은가? |
| 추론 강도 | none / low / medium / high | 단순 추출은 none, 대화는 low, 에이전트는 medium, 대량 자료 종합은 high |

에이전트라고 sol일 필요는 없다. 가벼운 에이전트는 luna로 돌린다.

## 3. 작업별 배치

| 사용자 작업 | 방식 | 모델 | 강도 | 도구 회전 | 이유 |
|---|---|---|---|---:|---|
| 자료 업로드·원문 추출·읽기 카드 | 워크플로 | 없음 | — | — | 파서로 충분하다. 지금도 모델을 안 쓴다 |
| 활동 후보 제안 | 워크플로 | 없음 → 애매할 때 luna | none | — | 폴더·단어 겹침이 1차 |
| 검색 키워드 생성 (`drive_workspace`) | 워크플로 | luna | none | — | 짧은 변환 작업 |
| 공고 분석 | 워크플로 | luna | low | — | 공고 텍스트를 구조화하는 단발 작업 |
| 사실 후보 뽑기 | 워크플로 (묶음 일괄) | luna | low | — | 호출이 많다. 모델은 줄 번호만 고르고 서버가 원문과 대조한다 |
| 활동 MD 작성 | 워크플로 | 없음 또는 luna | none | — | 확인된 사실만 조립한다 |
| **활동 MD 수정 요청** | 에이전트 (그 활동 범위) | sol | medium | 4 | 원문을 다시 찾아 읽고 기록으로 남는 글을 고친다 |
| **프로젝트 통합 요약** | 에이전트 (그 프로젝트 범위) | luna (기본) / sol ("정밀 분석" 버튼) | high / medium | 12 | 수백 개 파일을 다시 검색하며 구조를 찾는다. 가장 호출량이 큰 작업이라 기본은 luna |
| **챗봇 회상** | 가벼운 에이전트 | luna → 못 찾으면 사용자가 "더 깊게 찾기"를 눌러 sol | low / medium | 3 / 6 | 정답 원문만 찾으면 작은 모델도 정확하다(9/28 실험) |
| **공부 도우미** | 가벼운 에이전트 (내 자료 검색 도구 하나) | luna | low | 2 | 개념 설명은 바로 답하고, 내 자료가 필요할 때만 검색한다. 일반 설명은 경험 기록으로 저장하지 않는다(`derived`) |
| 공부 세션 요약 | 워크플로 | luna | low | — | 대화 한 번을 정리한다 |
| **자소서 대화** (질문·논의) | 에이전트 (계정 범위) | luna | medium | 3 | 근거 찾기와 되묻기 |
| **자소서 초안·수정** | 에이전트 | sol | medium | 3 | 사용자가 제출하는 글이다. 품질이 가장 중요한 곳 |
| 자소서 문장별 근거 판정 | 워크플로 | sol | low | — | 작성한 호출과 분리해 스스로 채점하지 않게 한다(F-203) |
| 프로필 종합 | 워크플로 | sol | low | — | 드물게 실행되고 여러 경험을 종합한다 |
| 임베딩 | — | `text-embedding-3-small` | — | — | 유지 |

**자소서를 두 단계로 나누는 이유:** 대화의 대부분은 질문과 확인이다. 이 부분을 luna가 맡고, 실제 초안을 쓰거나 고칠 때만 sol을 부르면 품질을 유지하면서 비용을 크게 줄일 수 있다. 현재 오케스트레이터가 `discuss/ask/draft` 중 하나를 고르므로, `draft`일 때만 sol로 다시 호출하는 식으로 구현할 수 있다.

**프로젝트 요약 기본을 luna로 두는 이유:** 9/28 첫 실행은 코드 기본값과 `.env` 설정으로 보면 **astra로 돌았는데도** 검증을 통과한 근거가 1개뿐이었다. 품질 문제의 원인은 모델 크기가 아니라 근거 대조·검색 과정이다. F-206 실험에서 luna가 부족하다고 나오면 sol로 올린다.

## 4. 비용 상한 대신 안전장치

사용자당 월 예산이나 작업당 금액 상한은 **두지 않는다.** 소규모 베타에서는 사용을 막는 부작용이 더 크고, luna·sol 가격이면 정상 사용으로는 큰돈이 나가지 않는다. 대신 **비정상 동작만** 막는다.

| 안전장치 | 막는 것 | 값 |
|---|---|---|
| 도구 회전 수 | 에이전트가 끝없이 검색 | §3 표 |
| 작업 시간 | 멈춘 요청 | 챗봇 60초, 자소서 90초, 프로젝트 요약 10분 |
| `max_output_tokens` | 추론 토큰 폭주 | 작업별 지정 (추론 포함) |
| 크레딧 소진 오류 | `insufficient_quota` 재시도 반복 | 즉시 중단, 화면에 안내 |
| OpenAI 조직 월 예산 | 전체 지출 | 사람이 결제 화면에서 설정 (유일한 금액 상한) |
| 호출 기록 | 어디서 돈이 나가는지 모름 | 작업·모델·강도·토큰·예상 비용·시간을 기록 |

## 6. 자체 루프 vs Agents API

기본은 **자체 루프**다. 계정 범위 도구를 우리가 통제하고, 가짜 모델로 테스트할 수 있고, 모델을 바꾸기 쉽다. F-206 실험(F-105 충전, F-201 평가셋 이후)으로 확인한다.

| 조건 | 실행 기반 | 모델 | 재검색 |
|---|---|---|---|
| A (현재) | 자체 | 4o-mini | 1회 |
| B | 자체 | luna low | 최대 3회 |
| C | 자체 | sol medium | 최대 3회 |
| D | Agents API | sol medium | 모델이 결정 |

한 번에 한 가지만 바꿔 비교한다. B가 A보다 좋으면 모델 교체와 재검색이 효과가 있는 것이고, C가 B보다 크게 좋아야 sol을 쓸 이유가 생긴다. D가 C보다 좋아야 Agents API를 쓸 이유가 생긴다.
