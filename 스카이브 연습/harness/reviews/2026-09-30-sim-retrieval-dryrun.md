- A = 현재 방식(질문 단어 그대로), B = 사람이 고른 이상적 검색어(영어 번역·동의어 포함). B는 좋은 키워드 확장이 있을 때의 상한을 보려는 것.

**요약:** 정답 있는 5문항 중 A top5 3/5, B top10 5/5. 검색 1회 약 25~30초.

### 원인

1. **텍스트 인덱스 없음 (B-004).** `drive_file_chunks`에 pg_trgm·전문검색 인덱스가 없다. 검색어마다 본문 전체를 ILIKE로 두 번(조건, 순위) 훑는다. 9/28 챗봇 응답 47초의 주원인으로 보인다. 9/29 자료가 추출되면 더 느려진다.
2. **조사·어미가 검색어로 들어감 (B-005).** "에서", "어떻게", "이랑", "비율은" 등이 검색어가 된다. 프로젝트 요약 보강 로직이 이런 일반어 일치만으로 발전소 통합 요약을 **6문항 중 5문항에서 1순위**로 끼워 넣었다.
3. **한국어 질문 ↔ 영어 문서 (B-006).** 실험 결과 보고서가 영어로 쓰인 경우가 많다. 번역·동의어 확장이 없으면 못 찾는다. 모델 키워드 확장(luna, reasoning none)에 번역을 지시하는 것이 가장 싸다.
4. **추출 전 자료를 모름.** 추출 안 된 파일은 검색 대상에서 빠지므로, 사용자가 그 프로젝트를 물으면 무관한 결과가 나온다. 파일·폴더 이름 메타데이터 색인(F-210)이 있으면 "해당 폴더 파일 3,246개는 아직 읽는 중"이라고 답할 수 있다.

## S2 활동 후보 결과

후보 13개가 나왔다. 실제 프로젝트 단위와 맞는 것은 **3개**(KT, 발전소 이상탐지, 건설장비 최상위 폴더)뿐이다.

| 문제 | 예 | 원인 |
|---|---|---|
| 의미 없는 내용 후보 | "관련 자료: using, with" (공통 단어 using, with, source) | 단어 겹침 비교에 영어·한국어 불용어가 없음 |
| 너무 큰 단위 | 9/29 업로드의 카테고리 폴더 3개(각 343~1,903개)를 활동 하나로 제안 | "최상위 아래 2단계까지"만 본다. 업로드가 감싸는 폴더 한 겹을 더 가지면 실제 프로젝트(3단계)가 후보에서 빠진다 |
| 작성자 폴더를 활동으로 제안 | 발전소 프로젝트 안의 작성자 이름 폴더(368개) | 하위 폴더가 하나뿐인 감싸는 폴더를 단계로 오인 |
| 한 프로젝트의 단계를 별도 활동으로 제안 | KT 안의 "whitelist", "TC생성" 폴더 | 단계 폴더와 프로젝트 폴더를 구분하지 않음 |
| 실제 프로젝트 누락 | 9/29 업로드 안의 수업·공모전·대회 프로젝트 약 10개가 후보에 없음 | 위 단계 제한 |

`drive_project_summary.py`에는 이미 "하위 폴더가 하나뿐인 감싸는 폴더를 건너뛰고, 처음으로 여러 폴더가 갈라지는 깊이를 찾는" 로직이 있다. 활동 후보에도 같은 판단을 쓰면 된다. **드라이브 화면의 폴더 구조는 바꾸지 않는다**(불변조건 5). 후보 계산에서만 쓴다.
