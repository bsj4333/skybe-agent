# Supabase 드라이브 경험 초안·UI 점검 (2026-09-23)

## 직접 실행한 것

- Edge headless에서 임시 Supabase 계정 로그인, 두 파일이 들어 있는 폴더 선택, 폴더 즉시 표시, 파일 전송, 원문/색인 열기, 경험 초안 열기를 클릭했다. 브라우저 오류는 없었고 임시 계정·파일은 정리했다.
- 같은 환경에서 로그인 0.9~1.2초, 폴더 표시 약 4초, 두 작은 파일의 업로드 완료 8.9~10초였다. 1,079개 파일 브라우저 업로드의 단계별 시간은 아직 측정하지 않았다. 전송 패널에 경과 시간·평균 바이트/초·개수·실패·전체 퍼센트를 표시한다.
- 기존 로컬 앱은 포트 8011에서 별도 실행했다. `/api/user`는 8011에서 200, 새 드라이브의 8010에서는 410이다. 8011의 다른 출처 요청은 403이고, 루프백에만 바인딩한다.

## 실제 자료에서 생성한 초안

| 폴더 | 업로드 파일 | 모델이 읽은 파일 | 제안 문장 | 자동 근거 검사 통과 |
| --- | ---: | ---: | ---: | ---: |
| KT | 701 | 20 | 12 | 7 |
| 화력발전소 이상탐지 | 369 | 24 | 12 | 8 |
| 건설장비 이상탐지 핵심 자료 | 9 | 9 | 12 | 0 |

KT는 프로젝트 정리본, README, 실험 설계·분석 등 여러 문서에서 인용을 남겼다. 화력발전소는 확인 가능한 문장 대부분이 `report.md`에 집중됐다. 건설장비는 표·코드 위주라 숫자와 주체를 함께 증명하는 경험 문장이 나오지 않았다. 자동 검사 통과가 0개인 폴더는 검증 보류 문장의 내용을 화면에 나열하지 않고 설명 문서와 본인 역할 기록을 요청한다.

`자동 근거 검사 통과`는 인용문이 선택한 원문에 존재하고, 문장 겹침·수치·주체 충돌 규칙을 통과했다는 뜻이다. 의미상 충분한 근거인지, 구버전과 충돌하는지, 사용자 본인의 기여인지는 아직 확인되지 않았다. **자소서에 자동으로 넣는 단계가 아니다.** 폴더별 AI 초안은 `skive.drive_folder_summaries`에 사용자 ID·폴더 ID·원본 버전 서명과 함께 보관하며, 파일이 바뀌면 화면에서 이전 초안으로 표시한다.

## 다음 구현 경계

1. 업로드 파일 전체를 대상으로 한 계층 요약과 구버전·중복·충돌 탐지. 현재 최대 24개 파일·100,000자만 모델에 보낸다.
2. 사용자 프로필에 실명·학년·프로젝트별 본인 역할을 별도 진술로 저장하고 확인 카드 제공. 원문에 팀 성과만 있을 때 본인 성과로 승격하지 않는다.
3. 새 계정별 경험·프로필·공고·챗·자소서 저장소와 API를 구현한 뒤, 기존 `writer.py`와 `chat.py`의 근거 검증 로직을 사용자 범위 안으로 이식한다. 포트 8011의 기존 기능은 현재 새 드라이브와 연결되지 않는다.
4. 이미지 OCR, 대형 XLSX 스트리밍 분석, 브라우저의 실제 대량 폴더 속도 측정과 재개 UX.
